# SAB Monitor

ระบบตรวจคุณภาพข้อมูลภาคสนาม — โครงการติดตามและประเมินผลการส่งเสริมกิจกรรมทางกายในโรงเรียน
ตามยุทธศาสตร์ Specific Area-Based Health Promotion (สสส. / IPSR มหาวิทยาลัยมหิดล)

ไฟล์เดียว ประมวลผลในเบราว์เซอร์ ไม่มีเซิร์ฟเวอร์ ไม่มีฐานข้อมูล

---

## การใช้งาน

1. เปิด `index.html` ในเบราว์เซอร์ (เปิดจากเครื่องโดยตรงได้ ไม่ต้องมีอินเทอร์เน็ต)
2. ลากไฟล์ผลสำรวจจาก LimeSurvey มาวาง — รองรับ `.csv` และ `.xlsx` **เลือกได้ทีละหลายไฟล์**
3. ระบบจับคู่คอลัมน์อัตโนมัติ แล้วแสดงผล 15 หน้า

**รูปแบบไฟล์ที่รองรับ** ส่งออกจาก LimeSurvey แบบ **“แสดงคำตอบเต็ม” (Full answers)** ทั้งหัวคอลัมน์และคำตอบ

> ใน LimeSurvey ไปที่ **Responses → Export responses** แล้วในหัวข้อ Headings และ Responses เลือก **Full answers** ไม่ใช่ **Answer codes**
>
> ถ้าส่งออกเป็นรหัสคำตอบ ระบบจะปฏิเสธไฟล์พร้อมบอกวิธีแก้ เพราะการตรวจอาศัยข้อความคำตอบโดยตรง และรหัสของ dropdown บางชุด เช่น ปีเกิด กู้กลับเป็นค่าจริงไม่ได้

### ถ้า LimeSurvey ดาวน์โหลดได้ทีละชุด

เลือกไฟล์ทั้งหมดพร้อมกันได้เลย ระบบรวมให้เองตามลำดับคอลัมน์ **อย่านำไปรวมด้วยเครื่องมืออื่นก่อน**

LimeSurvey เติมรหัสคำถามภายในต่อท้ายหัวคอลัมน์ที่ชื่อซ้ำกัน เช่น `มีสัปดาห์ละกี่วัน (Q368365)` และรหัสนั้นต่างกันในทุกชุดแบบสอบถาม เครื่องมือรวมไฟล์ทั่วไปที่จับคู่ด้วยชื่อหัวคอลัมน์จึงทำให้ข้อมูลจากชุดอื่นตกหล่นทั้งหมดโดยไม่มีข้อความเตือน ระบบตรวจจับบล็อกกิจกรรมทางกายจากรูปแบบหัวคอลัมน์ `N. ช่วง…` ที่ตามด้วย `มีสัปดาห์ละกี่วัน`

ระบบรองรับความต่างของโครงสร้างที่พบระหว่างรุ่นของแบบสอบถามโดยอัตโนมัติ ได้แก่ วันเกิดที่เป็นคอลัมน์เดียวหรือแตกเป็นสามช่อง (วัน / เดือนภาษาไทย / ปี พ.ศ.) ชื่อผู้สัมภาษณ์และชื่อโรงเรียนที่แตกเป็นหลายคอลัมน์ตามทีมและตามอำเภอ และหัวคอลัมน์ของมาตรวัดที่ตัดข้อความนำออก จึงใช้ไฟล์รุ่นเก่าและรุ่นใหม่กับระบบเดียวกันได้

### ภาพรวม

| หน้า | ใช้เมื่อไร | ใครใช้ |
|---|---|---|
| **หน้าหลัก** | ดูสถานะรวมประจำวัน | ผู้จัดการโครงการ |
| **ความคืบหน้า** | ตารางยอดเก็บ โรงเรียน × วันที่ วางแผนลงพื้นที่ | ผู้จัดการโครงการ |
| **QuickCheck** | ก่อนทีมเก็บของกลับ — เฉพาะรายการที่แก้ได้ทันที | หัวหน้าทีมสนาม |
| **ภาพรวมชุดข้อมูล** | ทุกสิ้นวันหรือสิ้นสัปดาห์ — จับปัญหาที่เกิดกับทั้งทีม | ผู้ควบคุมคุณภาพ |

### ตรวจรายเคส

แต่ละหน้าดึงเฉพาะข้อคำถามของส่วนนั้น ทั้งตัวเลขในเมนู แผงแจกแจง ตารางเคส และรายละเอียดที่กางออกมาเมื่อกดที่แถว

| หน้า | ครอบคลุม |
|---|---|
| **ข้อมูลทั่วไป** | วันเกิด อายุ ระดับชั้น เพศ ความซ้ำซ้อนของผู้ให้ข้อมูล |
| **PA เวลาเรียน** | ข้อ 1–16 พร้อมสัญญาณข้ามข้อและภาพรวมเวลากิจกรรมวันธรรมดา |
| **PA วันหยุด** | ข้อ 17 และข้อ 15–16 ที่ถามคาบทั้งสองช่วง |
| **เรียนพิเศษ** | ข้อ 18 |
| **หน้าจอ** | ข้อ 19 · การนอนหลับ (J01–J02) · ภาพรวมเวลารวมทั้งวัน |
| **ความพึงพอใจ** | ข้อ 20.1–20.3 และความสอดคล้องกับส่วนกิจกรรมทางกาย |
| **สุขภาวะในโรงเรียน** | มาตรวัด 9 ข้อ |
| **การบริโภคโซเดียม** | การแตกชุดตามอายุ ความครบถ้วน และความสอดคล้องภายในชุด |

> ข้อ 15 และ 16 ปรากฏทั้งในหน้า PA เวลาเรียนและ PA วันหยุด เพราะแบบสอบถามระบุว่าถามวันเสาร์อาทิตย์ด้วย ตัวเลขในเมนูสองหน้านี้จึงซ้อนกันบางส่วนโดยตั้งใจ ข้อที่ซ้อนมีป้าย “คาบ” กำกับ

### ทีมงานและตั้งค่า

| **เกณฑ์การตรวจ** | ปรับเกณฑ์เชิงตัวเลขทั้งหมดโดยไม่ต้องแก้โปรแกรม |

## แนวคิดหลัก

### หน้าต่างการแก้ไข

การสำรวจครัวเรือนกลับไปแก้ยาก แต่โรงเรียนแก้ได้ทันทีถ้าทีมยังอยู่ในพื้นที่ ทุกสัญญาณจึงติดป้ายว่า

- `แก้ที่โรงเรียน` — ต้องปิดให้ได้ก่อนทีมออกจากพื้นที่วันนั้น
- `ตามกลับภายในสัปดาห์` — โทรหรือกลับไปโรงเรียนได้
- `แก้ที่สำนักงาน` — เป็นปัญหาของระบบหรือการทำความสะอาดข้อมูล

หน้า **QuickCheck** กรองเฉพาะกลุ่มแรก จัดกลุ่มตามโรงเรียนและวันที่ พร้อมข้อความสั่งการรายบรรทัด

### สามระดับของการตรวจ

**ระดับเคส 85 สัญญาณ** — `I` ข้อมูลทั่วไป · `P` กิจกรรมทางกาย · `S` และ `D` เรียนพิเศษ หน้าจอ ภาพรวมเวลา · `X` ความพึงพอใจ · `Q` รูปแบบการตอบและ routing · `N` โซเดียม · `T` จังหวะการเก็บ

**ระดับชุดข้อมูล 8 สัญญาณ** (`B1`–`B8`) — ความผิดปกติที่มองไม่เห็นจากเคสเดียว เช่น ข้อคำถามที่เกือบทุกคนตอบว่าไม่มี หรือข้อความรู้ที่ทุกคนตอบเหมือนกัน

**ระดับผู้สัมภาษณ์ 4 สัญญาณ** (`Z2` `Z3` `Z4` `Z6`) — เปรียบเทียบกับค่าเฉลี่ยทีม

กด **อภิธานศัพท์** มุมขวาบนเพื่อดูคำอธิบายทุกสัญญาณ หรือกดที่การ์ดสัญญาณในแต่ละหน้าเพื่อดู “หมายความว่าอะไร / ควรทำอย่างไร”

## ตัวกรองและการส่งออก

**ตัวกรองสัมพันธ์กัน** — เลือกโรงเรียนแล้วช่องผู้สัมภาษณ์เหลือเฉพาะคนที่เก็บโรงนั้น และย้อนกลับด้วย ทุกตัวเลือกมีจำนวนเคสในวงเล็บ ถ้าเลือกคู่ที่เข้ากันไม่ได้ ระบบรีเซ็ตให้พร้อมแถบเหลืองอธิบายเหตุผล

**รายงานสรุป PDF** — ใช้ตัวกรองที่ตั้งไว้บนหน้าจอ กดแล้วเด้งหน้าต่างพิมพ์ของเบราว์เซอร์ เลือก Destination เป็น *Save as PDF*

> เปิด **Background graphics** ในเมนู More settings ด้วย ไม่งั้นพื้นหลังหัวตารางจะหายไป

**ส่งออก CSV** — รายการที่ต้องตรวจรายเคส สำหรับพิมพ์แจกทีมสนามหรือเปิดต่อใน Excel

## การปรับเกณฑ์

ค่าเริ่มต้นของ **เพดานนาทีรายข้อ** ตั้งจากโครงสร้างเวลาเรียนของโรงเรียนไทย ไม่ใช่จากข้อมูลจริงของพื้นที่

> **ต้องปรับหลัง pre-test** ก่อนใช้เก็บจริง

วิธีปรับ ไปหน้า **PA เวลาเรียน** หรือ **PA วันหยุด** → ตารางสรุปรายข้อ ดูคอลัมน์ “นาที มัธยฐาน” และ “ต่ำสุด–สูงสุด” → ถ้าข้อไหนมีเคสเกินเพดานจำนวนมากทั้งที่ดูสมเหตุผล ให้ขยายเพดานในหน้า **เกณฑ์การตรวจ** แล้วกด “คำนวณใหม่”

ค่าที่แก้อยู่ในหน่วยความจำเท่านั้น ถ้าได้ค่าที่ลงตัวแล้วให้แก้ค่าเริ่มต้นใน `PA_ITEMS` และ `MISC` ที่ต้นไฟล์ `index.html` แล้วบันทึกเหตุผลไว้ใน `CHANGELOG.md`

## ระยะเวลาสัมภาษณ์

ระบบตรวจหาคอลัมน์เวลาอัตโนมัติ พบก็เปิดใช้สัญญาณ `T1`–`T3` เอง ไม่พบก็ถอยไปใช้ระยะห่างระหว่างเคสของผู้สัมภาษณ์คนเดียวกันแทน ไฟล์เดียวรองรับทั้งสองแบบ

ก่อนลงสนามให้เปิดใน LimeSurvey ที่ Survey settings → Notification & data management

- **Date stamp** → ได้คอลัมน์ `startdate`
- **Save timings** → ได้คอลัมน์ `interviewtime` (สำคัญกว่า เพราะไม่เพี้ยนเมื่อเปิดแบบสอบถามค้างไว้)

ต้องเปิดก่อนเริ่มเก็บ เพราะไม่ย้อนหลังให้ และตอน export ต้องติ๊กให้รวมคอลัมน์เวลามาด้วย

เกณฑ์ `T1` `T2` คิดเป็นเปอร์เซ็นต์ของมัธยฐานทีมในไฟล์นั้น ไม่ใช่ตัวเลขนาทีตายตัว จึงปรับตัวตามข้อมูลจริงเองโดยไม่ต้องแก้เกณฑ์ทุกรอบ

## ข้อจำกัดของไฟล์ส่งออกปัจจุบัน

เงื่อนไขต่อไปนี้ออกแบบไว้แล้วแต่ยังทำงานไม่ได้ (ดูรายละเอียดในหน้าอัปโหลด)

| ฟิลด์ที่ขาด | ผลกระทบ |
|---|---|
| ความยินยอมผู้ปกครองและ assent | ตรวจความครบถ้วนด้านจริยธรรมไม่ได้ |
| รหัสประจำตัววิจัย | เชื่อมทะเบียนนักเรียนและ match รอบ Midline/Endline ไม่ได้ |
| รหัสโรงเรียน | เทียบกับทะเบียน 65 โรงไม่ได้ (ห้องเรียนมีแล้วตั้งแต่ v1.3) |
| ทะเบียนเป้าหมายรายโรงเรียน | หน้าความคืบหน้าแสดงได้แค่ยอดดิบ ไม่ใช่เปอร์เซ็นต์ความคืบหน้า (สัญญาณ R1–R5) |
| สถานะเคส (สำเร็จ/ปฏิเสธ/ไม่พบตัว) | คำนวณอัตราการตอบและอัตราปฏิเสธไม่ได้ |

## ความปลอดภัยของข้อมูล (PDPA)

- ประมวลผลทั้งหมดในเบราว์เซอร์ ไม่มีการส่งข้อมูลออก ไม่มีเซิร์ฟเวอร์
- ปิดหน้าเว็บ = ข้อมูลหายจากหน่วยความจำทันที
- `index.html` ไม่มีข้อมูลผู้ตอบฝังอยู่ จึงเผยแพร่เป็น public repo ได้
- **ห้ามอัปโหลดไฟล์ข้อมูลเข้า repository** เพราะมีชื่อ–สกุลจริงและวันเกิดของนักเรียน

## Deploy ขึ้น GitHub Pages

```bash
git init
git add .
git status          # ← ตรวจว่าไม่มีไฟล์ .csv หรือ .xlsx โผล่ในรายการ
git commit -m "SAB Monitor v1.2"
git branch -M main
git remote add origin https://github.com/<username>/sab-monitor.git
git push -u origin main
```

จากนั้นไปที่ **Settings → Pages** แล้วตั้ง Source เป็น GitHub Actions

อัปเดตเวอร์ชัน แทนที่ `index.html` แล้ว push — ถ้ายังเห็นของเก่าให้กด `Ctrl+Shift+R` ล้างแคช

## ไฟล์ในรีโพนี้

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | ตัวระบบทั้งหมด ไฟล์เดียวจบ ไม่มีขั้นตอน build |
| `README.md` | คู่มือผู้ใช้ |
| `CONTRIBUTING.md` | คู่มือสำหรับผู้ดูแลและแก้ไขระบบต่อ |
| `CHANGELOG.md` | บันทึกการเปลี่ยนแปลงและเหตุผลของการปรับเกณฑ์ |
| `.gitignore` | บล็อกไฟล์ข้อมูลผู้ตอบไม่ให้หลุดเข้ารีโพ |
| `.gitattributes` | บังคับ LF และไม่นับ `index.html` เป็นโค้ดของโครงการ |
| `.nojekyll` | ปิดการประมวลผลด้วย Jekyll บน GitHub Pages |
| `.github/workflows/deploy.yml` | deploy อัตโนมัติเมื่อ push |

เอกสารข้อกำหนดเงื่อนไขการตรวจฉบับ Word ไม่ได้อยู่ในรีโพนี้ เพราะภาคผนวกอ้างถึงโรงเรียนนำร่องและผลการตรวจของโรงเรียนนั้น ให้ขอจากผู้ดูแลโครงการ
